# ADR-0008: Project Layout and Toolchain Baseline

Status: Accepted for bootstrap phase  
Date: 2026-10-07  
Issue: #30

## Decision

AI CLI Orchestrator uses the following bootstrap baseline:

- Node.js 24.21.0 LTS
- pnpm 12.9.1
- Rust 1.99.0 stable
- React 19.3.0
- TypeScript 7.0.2
- Vite 8.3.3
- @vitejs/plugin-react 6.1.2
- Tauri 2.x, with current stable JS tooling verified at @tauri-apps/cli 2.12.1 and @tauri-apps/api 2.12.1

The Rust-side Tauri crate versions are not guessed in this ADR. They must be resolved from the current official Tauri 2 scaffold/package metadata during the application scaffold PR and committed through Cargo.lock.

## Package manager

Use pnpm.

Reasons:

- current Tauri create-project documentation uses pnpm as its recommended/default walkthrough choice;
- pnpm produces a deterministic pnpm-lock.yaml;
- strict dependency visibility helps prevent undeclared dependency access;
- it is suitable if the repository later becomes a multi-package workspace;
- it supports macOS and Windows.

When package.json is introduced it must contain an exact packageManager field.

## Workspace layout

Planned structure:

```text
/
├─ src/                         # React frontend
├─ src-tauri/                   # Tauri application shell
├─ crates/
│  └─ orchestrator-core/        # UI-independent Rust domain/core
├─ docs/
├─ Cargo.toml                   # Rust workspace
├─ Cargo.lock                   # committed
├─ package.json
├─ pnpm-lock.yaml               # committed
├─ rust-toolchain.toml
└─ .node-version
```

## Core boundary

`crates/orchestrator-core` must not depend on the desktop window lifecycle.

It owns provider-independent domain logic such as:

- Workspace / Task / Run state
- routing contracts
- session identity contracts
- permission policy contracts
- workspace lease contracts
- recovery contracts
- persistence abstractions

The Tauri shell may depend on the Core crate, but Core must remain unit-testable without launching the desktop UI.

## Toolchain pins

`.node-version` pins the Node LTS baseline used by contributors and CI.

`rust-toolchain.toml` pins the Rust compiler and includes rustfmt/clippy.

Package and Cargo lockfiles will be generated by actual package managers during the scaffold PR. They must not be handwritten.

## Version policy

These versions are the verified bootstrap baseline on 2026-10-07.

Future dependency updates:

- use normal dependency-update PRs;
- include release-note/compatibility review;
- update lockfiles;
- run macOS/Windows CI;
- record licensing/NOTICE changes;
- avoid floating `latest` in committed manifests.

Provider CLI versions are not pinned by this ADR. Provider compatibility remains capability-probe based.

## Security

- no provider binary is bundled by default;
- Tauri capabilities/permissions begin with least privilege;
- dependency installation must preserve lockfiles;
- third-party license obligations are reviewed before merge;
- package lifecycle scripts are treated as supply-chain-sensitive.

## Consequences

Benefits:
- reproducible contributor/CI baseline;
- explicit frontend/core separation;
- independent Core tests;
- predictable cross-platform setup.

Costs:
- toolchain upgrade PRs are required;
- separate Rust and JS dependency graphs must be maintained;
- lockfile changes require review.
